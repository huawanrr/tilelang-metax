# 928 同步分桶试验

以固定的 927 next 源码为基线。这里只保留实验，未修改任何提交文件。

`probe_bounded_atomic.py` 证明显式约束索引后，共享内存的返回旧值原子加
可以编译并正确分配唯一槽位；全局内存版本仍在 AccessPtrLowerer 失败。
原笔记中“返回旧值原子加一律不可用”的判断应缩小到已失败的全局内存路径。

`prepare_kernel.py` 用共享原子计数、token scatter 和前缀和，在一次发射中
完成原来两次发射的分桶和任务表生成。预处理阶段全局访问保持边界检查。
直接在 T.Parallel 中使用返回槽位会布局推断失败，现改为显式线程号加串行
分段循环。原失败源码保留为 `prepare_parallel_rejected.py`。

四个 attention 变体每 CTA 处理 2/4 个选择相同 KV 块的查询，分别使用
2/4 个 64-lane wave，或单个 wave 内增加 MMA 行数。12 个候选形状参考
检查均通过（oj6/case69/case83），最大绝对误差 0.001953125。

| 方案 | oj6 基线 / 候选 us | case69 | case83 |
|---|---|---|---|
| 2 查询、多 wave | 136.29 / 172.44 | 76.76 / 101.82 | 28.37 / 44.05 |
| 4 查询、多 wave | 136.29 / 148.42 | 76.76 / 87.49 | 28.37 / 37.50 |
| 2 查询、单 wave | 136.67 / 160.07 | 81.23 / 106.64 | 31.18 / 51.84 |
| 4 查询、单 wave | 136.67 / 155.25 | 81.23 / 102.60 | 31.18 / 50.96 |

共享 GPU 其他 slice 持续有负载，以上只反映同轮交替测量；仍未看到可采纳
信号。4 查询多 wave 的独立分段测量：准备 11.95us、attention 134.65us，
attention 本身没有足够改善来抵消准备开销。此轮任务表完整性检查确认每个
token 恰好出现一次，任务的 KV 块与运行时输入匹配。

另有 `schedule_checks.json`：24 个任务表边界场景各跑两次，通过全同索引、
全无效索引、混合索引、末尾块，以及 N=1/31/33/255/257/1025、H=1/2 和
因果/非因果组合。每次将工作区重填 -999，确认无遗留内容依赖。

编译器对数据依赖的输出 scatter 报 race 警告，无法静态证明 Sorted 元素唯一。
未关闭检查；目前仅为研究代码，未提交或宣称通过正式沙箱。

本地诊断 `kernel_source.py` 已支持读取 prepare/attention 闭包中的源码，
没有向可调用函数写入属性。无异步拷贝，索引与工作区每次调用均重新生成。

## 分桶与 attention 融合

`fused_template.py` 在每个 CTA 内扫描一个查询区间，选择同一 KV 块的查询，
共享内存前缀和生成本地任务顺序，再分组计算。省去独立预处理发射和所有
全局任务表，QK/PV 使用原同步路径。比较 QT/CQ=2/128、4/128、4/256、4/512。

12 个候选形状参考检查全部通过；但 oj6 约 352–481us 对基线 131us，case69
约 226–363us 对基线 65us，case83 约 200–346us 对基线 26us。显著回退，
不采纳。原始四轮数据在 `fused.json`；循环、扫描与任务不均衡的成本远大于
节省的发射/工作区成本，不再对此结构做细粒度调参。所有四份源码静态检查通过，
数据依赖输出 scatter 仍有编译器 race 警告，未关闭检查。

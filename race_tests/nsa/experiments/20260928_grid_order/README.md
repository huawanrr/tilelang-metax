# 928 CTA 遍历顺序与 PV 累加组合

对 next 的 S1 emitter 和 packed S8 分别改变 CTA 遍历顺序：token 逆序、
batch/KV-head 交错、两者组合。只改变查询执行顺序，单查询数学保持原样。
S1 没有采纳信号；S8 的 batch 交错继续与四份 PV 累加器组合比较。

`order.json` 保存3个候选×5个形状，`families.json` 保存4个候选×8个形状的
参考检查及交替计时。原始时间中可见其他 GPU slice 引起的显著漂移，例如
oj12基线在53–73us间变化，不能直接解释某些中位数的17%提升。

## 更长的夹测

`long_bracketed.json`：每个候选 A/B/A 48次，每次1000调用；输入/输出地址
相同，每次公开调用重新打包 K/V，加入与A完全同源的控制。下表为两侧基线
漂移≤1%的样本中位加速比：

| 形状 | 同源控制 | 交错batch | 交错batch+四累加器 | 再加token逆序 |
|---|---:|---:|---:|---:|
| oj12 B4/T1024/H1 | 0.99882 | 1.03175 | 1.02019 | 1.02256 |
| B8/T512/H1 | 0.99853 | 1.04113 | 1.06185 | 1.07039 |
| B8/T1024/H1 | 0.99624 | 1.01399 | 1.08885 | 1.08443 |

oj12有41–44个低漂移候选样本，其他形状各19–28个左右；仍不等于完全排除
B窗口里的外部干扰。此轮以相同网格规模制定简洁门限：4096–8191只交错batch，
≥8192再加四累加器。小网格、S1及S16保持next，不单独拟合B8/T512特例。

该分派已整理并验证为 `../20260928_s8_order_oj/submission.py`，完整发布证据
以那个目录的清单为准。原 next 及 PV32 试验保持原哈希，尚无新官方分数。

## 复现

`make_candidates.py` 生成顺序变体；`make_combinations.py` 生成组合和只扩充
命名形状的本地计时工具。`bracketed_families.py` 在既有夹测工具上只增加
命名形状，保存所有样本，包括未通过漂移筛选的样本。

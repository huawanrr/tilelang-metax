成组 shared staging 的布局转换。QK 部分和拆的是同一块的 D 归约维，区别于
此前多个选中块之间的独立 score 累加器。

## 计时限制与加长复测

各筛选运行使用现有 `compare_same_output.py`：相同输入和输出指针、公开
`run_kernel`、100 次调用/CUDA graph、7 个样本、四轮交替顺序、约 40 ms
预热。计时包含打包 kernel。GPU 工作串行执行，未修改正在运行的模块。

本轮中途其他 GPU slice 开始运行。整卡有明显负载而本 slice 空闲；基线 oj6
在约 109–136 μs 间变化，oj12 在约 53–72 μs 间变化。原始 JSON 的部分几何
平均数受此影响，不能直接作为采纳排序或 OJ 提速预测。

新增 `compare_bracketed.py` 固定捕获 graph，在每个候选前后各测一次基线
（A/B/A），保留全部原始三元组；只将两侧基线漂移 <=1% 的三元组纳入摘要。
同时测同源 baseline/baseline 对照。该筛选不能排除只发生在中间 B 的负载
变化，所以不会仅凭“accepted”标记宣称测量可靠。

`pv_bracketed.json`：20 次/形状，覆盖 7 个形状，PV32/64 的初步复测。
`pv_confirm.json`：PV32 在 oj6/case69/case70 上各加长到 64 次：

| 形状 | 同源对照中位比 | PV32 中位比 | PV32 低漂移样本 |
|---|---:|---:|---:|
| oj6 | 1.00226x | 1.00451x | 10/64 |
| case69 | 1.00716x | 1.02394x | 15/64 |
| case70 | 0.99525x | 1.01846x | 19/64 |

有效样本比例低，候选/对照经历的负载状态不同，且 oj6 的差异接近对照偏差。
保留 PV32 作为待空闲环境复测的研究方向，不添加新的形状分派。

生成代码确认 PV32 的每线程输出累加数组从 32 个 float 缩为 8 个，V MMA
临时数组从 32 个 half 缩为 8 个；这不是机器码寄存器数或实际占用率测量。
共享 V 重排仍使用原来的单个共享缓冲；没有增加异步操作。

- 16 个候选的 68 个形状正确性检查，加上 31 个基线检查，共 99 项 PASS；
  两轮 A/B/A 运行还在各自计时前检查了输出。
- 使用原有 float32 稀疏参考与原有容差，最大绝对误差 0.001953125。
- 17 个源码（含基线）通过现有静态提交检查，79 份生成源码无检查列表中的
  异步标记。五个 host 函数 AST 与基线一致，四个原提交文件 SHA256 不变。
- 共享 V 的非线性索引可能触发编译器保守 race warning。穷举了 BS/D 各
  16/32/64 × 32/64/128 共 9 种映射，验证唯一写入、完整覆盖和 swizzle 逆映射。
- 因没有选中新版本，本轮没有重复全量 125 例、边界套件或完整沙箱验证。
  这里的筛选 PASS 不能解释为实验源码已适合提交。

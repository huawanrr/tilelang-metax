# 928 扩宽同步 QK 加载

旧结论“QK k_pack=4/8 不可用”来自 emitter 的布局选择函数仅接收 k_dim
4/16/32。`make_candidates.py` 改用显式 T.Fragment 和同步共享内存读取，
保持现有公开 MMA emitter，没有后端改动、类定义、函数属性写入或异步复制。

对于 KP=2/4/8，一个 lane 读取 KP*4 个连续 K 维元素。Q 与 K 使用相同
排列，每次 MMA 处理其中四个元素；KP 次 MMA 和四组 lane 覆盖 KP*16 个
K 维元素。改变累加顺序，仍完整计算原点积。QK 输出与 PV 的布局保持兼容。

三个变体在 oj6/case69/case83 的 9 个参考检查全部通过，最大绝对误差
0.001953125。手写 KP2 控制版本与 next 基线在 oj6 的设备源码逐字相同。

| 方案 | oj6 基线 / 候选 us | case69 | case83 |
|---|---|---|---|
| KP2（控制） | 136.98 / 136.43 | 81.29 / 81.07 | 31.14 / 32.31 |
| KP4 | 136.98 / 136.07 | 81.29 / 81.27 | 31.14 / 31.24 |
| KP8 | 136.98 / 140.80 | 81.29 / 83.58 | 31.14 / 32.69 |

KP4 目前持平、KP8 回退，未据此改动提交分派。原始四轮交替计时见
`wide.json`，GPU slice 争用及同源对照偏差仍明显。没有把编译障碍已解决
当成性能提升，也没有重复同一套原来编译失败的尝试。

`make_online.py` 另将 S8 的 K 打包宽度改为64，与 KP4 的 fragment 匹配；
QK 从两步变为一步加载组，K/V 打包仍在每次公开调用内执行。S8 结果另记于
`online.json`，此目录均为研究代码，不是新的 OJ 提交。

S8 三个代表形状参考检查全部通过。小网格 case80 慢约8%，大网格 oj12
同轮明显回退；case81 的基线/候选均存在约20–28us的分段漂移。三例几何平均
加速比0.91582，无采纳依据。原来的 V 打包映射没有修改，仍有编译器对非线性
索引的 race 警告；没有关闭检查。

# 928 分片复用小 KV 共享缓冲

S1/D128/BS32 按特征维切成64或32列，分别复用4KiB/2KiB的共享KV tile。
QK的K维分片累加到同一score，PV分片计算输出；提前归一化概率。对比完整
K/V寄存器暂存与逐片加载两种方式，共4个候选、12个参考检查通过，最大
绝对误差0.001953125，已知静态提交限制检查通过。

这四个实现均回退，不纳入提交。完整暂存时 oj6 约133.62→325.78/393.89us；
逐片加载也未抵消额外分段搬运和同步的成本。各形状四轮数据保留在
`shared.json`、`streamed.json`，不要将减少共享字节数直接当成占用率改善。
本次没有测机器码寄存器数或实际 occupancy。

## 布局推断修复记录

1. K/V fragment无显式布局：`no available layout found`。
2. 按原始行主序合并加载的布局：切片只覆盖部分线程，变量kt使loop layout
   无法验证可逆；`T.unroll`在该检查前尚未完全展开。
3. 在Python生成阶段展开kt/vo，仍因固定非零线程偏移不能归一化迭代器而失败。
4. 最终按特征片组织完整K/V fragment，每片覆盖全部64线程，并保留源码阶段
   的静态展开，编译及参考检查通过。逐片加载则只保留一个特征片的寄存器。

`template_inference_rejected.py`、`template_coalesced_rejected.py`和对应日志保留
失败证据。模板/生成器用于研究，公开包装仅分派D128/BS32形状。没有关闭race
检查、异步复制或外部设备源码。S8已发布试验和原PV32试验均保持原哈希。

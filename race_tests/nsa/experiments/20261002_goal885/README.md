前一组结果为 `register_qk_screen.json`，后一组为 `k_only_screen.json`。
所有候选参考检查通过。`register_qk_resources59.json` 保留匹配设备源码的
全部缓存资源记录；同一源码可以对应不同编译参数，不能随意选一条归因。

`coalesced_schedule_screen.json` 和 `coalesced_schedule_resources59.json`
验证了延后 V 确实减少寄存器数量，但没有转化为速度收益。并行 Q/K 在生成代码中
分别占据 4 KiB shared 区域，所增加的占用不能被减少的同步抵消。

`guard_multiseed.json`：24形状、3种子、每组24次A/B/A、每图500调用，
全部参考检查通过。66个改动形状/种子组合几何平均1.00514×，但有稳定反例：

grid≥4096的33个组合为1.00582×，最差0.99847×；这是待进一步确认的范围，
尚未据此发布新版本。逐形状汇总为 `guard_multiseed_summary.json`。

`block_view_screen.json` 的三个变体确实去除了重复边界判断，但case43的
private memory从0增至68字节，见 `block_view_resources43.json`。
离线编译相同设备源码得到的 LLVM IR 保留 `K_reg`/`V_reg` 两个私有数组和
global/private/shared之间的 memcpy；正常 guard 对照没有这些私有数组。
这属于未提升到寄存器的暂存，不能简单归因为寄存器压力溢出。
`block_view_ir_compile.json` 记录离线命令与输出；没有修改后端。

`block_view_staging_screen.json` 中，FP32暂存恢复了一部分性能，但仍慢约9%；
copy的coalesced_width提示被现有显式fragment布局覆盖，2/4两版设备码与原视图相同。
另一个仅用于CPU诊断的逐元素读取C++去掉了两个LLVM私有数组，见
`block_view_scalar_diagnostic_compile.json`；该诊断源码不被提交或GPU测试加载。

## 采用成对读取

`make_block_view_loads.py`将读取改为纯TileLang表达。单个half虽然消除了私有数组，
仍产生很差的性能；成对half形成原生uint32读取，并保留原8元素lane布局和7处同步。
case59的成对版本private memory为0、mtreg62、streg20，见
`block_view_loads_resources59.json`。所有参考检查通过。

`pair_loads_multiseed.json`用24形状、3种子、24次A/B/A、每图500调用复核。
20个改动形状的60个组合全部加速，几何平均1.05634×，范围1.01842–1.12445×；
4个未改动形状为1.00013×。原始样本、拒绝样本和逐形状汇总均保留。

`../20261002_blocks_v1`是首次整合：41个D32 v1非分派函数AST保持原样，
只新增builder并修改统一分派。额外12种短序列/多head/非因果形状的3种子夹测中，
D128稳定获益，但D64/T32的一种子为0.99301×，D64/T64为0.99031/0.98827/1.02330×。
因此`assemble_release_v2.py`将D64整个seq_len<128区间回退到D32 v1；
D128仍启用完整块。没有按测试编号或输入内容分派。

短序列边界补测保存在初版`d64_short_boundary.json`。D64/T128/B32仍有单种子
0.98988×，另外两个为1.00823/1.03181×；这个边界限制没有被删掉，也不能据此
声称任意输入都加速。96/112长度的正收益同样保留，但最终未启用这些短序列。

最终候选 **`../20261002_blocks_v2`** 的109例全量同轮比较已经完成：
相对D32 v1几何平均1.00599530×，18个新增改动用例全部加速、子集1.03586008×，
91个不变用例1.00019078×；相对87.93分10.1版为1.02331640×。
相对10.1的4个负结果均是本轮未修改的D32路径，保留在full.json，不把它们删除。

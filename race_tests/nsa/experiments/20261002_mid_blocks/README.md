|---|---:|---|

| 成对half读取 | 1.029460× | 扩展验证后仅采用H1 |
| 四half读取 | 1.028209× | 不采用 |

`bracketed_multiseed.json` 覆盖26形状、3种子、每组24次A/B/A、每图500调用。
最终H1范围的19形状/57组合：成对方案1.05033027×，四half方案1.04630979×。

## 原生uint32暂存试验

`make_word_views.py`将全局和局部暂存改成同字节uint32视图，分别读取1/2/4个word。
6形状初筛为1.023833/1.035500/0.622332×，同轮成对half为1.033065×。
4个word方案再次出现68字节private memory，保留在`word_views_resources72.json`。
虽然1/2个word使该形状mtreg由34降到32，但这并不保证加速。

`word_views_multiseed.json`再次以相同26形状/3种子对照成对half和2个word方案。
最终H1范围分别为1.05088090×和1.02902366×，后者有10个负组合，因此不采用。
成对half有两组小幅回退，最小0.994909×；同源控制0.998532–1.001313×。
全部接受/拒绝样本与逐形状汇总都保留，没有用单次最优值取代多种子证据。

`coalesced_words2.py`另将2个word暂存用于v2已经启用的大网格路径。
7形状平均0.996809×，5个形状变慢，不采用，也未改变最终候选的大网格路径。
CPU证明均读取实际loader/store的AST索引，覆盖lane归属、shared双射和同字节视图；
失败方案也通过正确性检查，未因性能不佳删除证据。

## 最终整合与验证

`assemble_mid.py`只对完整块、单KV head、`256 < B*H*T <= 2048` 的默认路径
加入成对读取builder，43个原有非分派函数AST保持原样，显式调参保持原路径。
共享布局、5处wave同步和输出写入保持不变，没有额外kernel启动。

最终109例同轮全量对比：相对87.93分10.1为1.03331689×，相对blocks_v2为1.00538177×。
11个新增改动用例平均1.05700880×；其中case28为0.984461×、case52为0.994641×。
两例都属于网格2048，该区间的case40有正收益；最终沿用统一网格范围，不按用例编号分派。
这些结果及之前较好的夹测都保留，不能只选正向记录，也不能把子集收益当作全量提升。

125例严格FP32双接口参考、34个边界/源码/发射大小核对、6组极端索引、24项调参等价、
4项原有不支持结果、18次同地址输入更新、6组host guard全部核对通过。
109例开发/提交/实际计时源码一致，传统18组等价检查通过。

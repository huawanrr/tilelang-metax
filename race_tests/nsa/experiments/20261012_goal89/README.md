## 本轮筛选

- `dispatch_small.json`：v9 小 D32 在当前两 seeds 比 v6 快约 4%，其他已有读取路径更慢。
- `dispatch_mid.json`：v9 的多头归约/掩码在 oj13 比 v6 快约 8%–9%；旧分母路径更慢。
- `dispatch_large.json`：大 D64 保留 v9；Q4 仅有约 0.1%–0.5% 的混合信号，不合入。
- `reduction_mid.json` / `reduction_short.json` / `reduction_large.json`：
  四项成对求和未复现历史较大的收益，部分 seed 回退，未采用。
- `pv_tiles.json`：PV32 的 oj14 初筛约 2.2%–2.6%，但 oj13 和 D128 回退。
  `pv_family.json` 第二轮在原形状和相邻 H2 形状出现反例，主动停止扩展；
  `pv_family_stop.json` 记录原因，驱动的 `FAIL`/SIGINT 和已有完整行均保留。
  没有采用更窄 PV 或求和组合。预备的 `balanced_family` 未运行。
- 第一版 `public_cache.py` 只节省约 0.2 μs CPU 分派，实际调用收益不清楚，未采用。
- 第二版 `public_cache_fast.py` 的纯 CPU 分派约 1.36→0.76 μs。
  152 个配置、8,208 次请求、整数/浮点/字符串参数、显式调参与默认路径交错、
  缓存清除都与父版一致；另 23 项 NumPy、不可哈希参数、同对象 Torch 标量更新通过。
  所有新增缓存 key 都检查为内建标量，当前调用输入保持传递。

`public_fast_loop.json` 是实际 `run_kernel` 调用，CPU 固定到同一个可用核心，
父版、同源控制和候选使用相同设置。9 个形状 × 2 seeds 的未过滤几何平均
为 **1.036958×**，同源控制 **1.000010×**；过滤后为 1.032177× / 0.994549×。
小形状大多提升约 3%–11%，受 GPU 限制的 oj6/oj9/oj12 接近持平。
这是相对 v9、包含 Python 发射间隙的结果，不是 GPU 图计时或正式分数。
候选与该 probe 的字节完全相同，原始正负样本和漂移数据均保留。

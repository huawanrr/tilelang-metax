# NSA 88.93 → 89.33，2026-10-14 接续

正式基线是 `../20261013_mfma_fix/submission.py`，SHA256
`71dd44e50e32a83a3758f656cf5ffcd757acae853546d69a226ec185bb18df92`。
用户确认该版为 88.93 分。本目录保存新研究，不覆盖历史提交或结果。

恢复会话 `01a13319-4503-7962-b98d-14460d7e758f` 后，已经核对上次收完的结果：
V 读取顺序在冷缓存的相邻形状上存在重复回退，不采用；小 D32 的两步
Newton 倒数在两个种子冷测中分别为 1.0567×、1.0610×，待进一步验证。
三步 Newton 与直接输出写回均无可采用收益。

新的打包研究将 K/V 放进同一次调用内分配的共同缓冲区，比较分平面、
按稀疏块交错以及每 512 个 half 交错的布局。它减少一次临时分配，
同时检查邻接 K/V 的地址生成和缓存局部性。每次调用仍从当前输入重新打包。
所有比较串行执行 GPU 工作，使用同源控制、独立 FP32 参考及实际公开入口，
计时包含全部打包和注意力 kernel。FP32 MMA 字符串类型修复保持。

本地结果不能作为已达到正式 89.33 的证明；新版本仍需正式评测确认。

## 已完成的筛查

- `joint_pack_screen.json`：K/V 共同分配在 BS32/S1 上有小幅信号，S8 的块交错
  和 chunk 交错重复回退。后续仅研究 BS32，并改用显式多维张量描述布局。
- `s8_pairs_screen.json`：减少 K 预读寄存器、增加 V 预读、交错 QK、减少累加器
  均未取得可采用收益。
- `denominator_screen.json`：S1 后置分母、FP16 分母和两步倒数组合没有普遍收益。
- `operand_butterfly_screen.json`：Q/K 的寄存器 butterfly 重排通过元素归属证明，
  实测仍回退，不采用。
- `small_math_screen.json`：小尺寸倒数的热测受形状与种子影响，不能直接推广。
- `single_guard_plain_screen.json`：合并有效性分支仅在打包 BS32 上有收益信号，
  其他 S1 路径回退。`T.likely` 版本不被当前 codegen 支持，失败日志保留。
- `short_waves_r2_screen.json`：两波独立计算稀疏块再合并，参考结果通过，但
  S2/S4 全部明显回退。初版的 eager lambda 作用域错误保留在初版日志。
- `short_sum_r2_screen.json`：FP32 MMA 归约与两步倒数组合在 S4 热测约
  1.006–1.014×；纯归约与纯倒数没有一致收益。初版晚定义 lambda 的错误已修复，
  原文件和初版部分结果保留。
- `bs32_focus_screen.json`：仅改默认 BS32/S1。共同缓冲区与合并分支组合在
  oj6 两种子为 1.01268× / 1.01285×，case69 为 1.00629× / 1.00686×。
  FP32 MMA 分母变体无收益。多维 joint 布局避免初版扁平地址表达。
- `memory_schedule_screen.json`：14 个 OJ 形状、两个种子，五组内存调度参数。
  中、大 S1 普遍回退；S2/S4 的表面信号需实际设备指令核对，尚不采纳。

`compiler_offline` 漏掉 fast-math，只作为失败的预筛证据保留。
`compiler_offline_fast` 补齐 `-use-fast-math` 后，八个形状的默认 `.text` 均与
正式基线实际 JIT 的二进制一致。若参数不改变设备指令，不将计时差异作为优化。
